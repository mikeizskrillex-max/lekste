# Lėkštė v2 — правила проекта

Персональный AI-планировщик питания для Литвы: меню на неделю под цель и бюджет → самая дешёвая корзина в Barbora или Rimi → список покупок со ссылками на товары. ТЗ — `SPEC.md`. Решения владельца, которые меняют ТЗ, — `docs/decisions.md`; при расхождении действует `docs/decisions.md`. Код v1 (ветка `v1-final`) **не переиспользуем**.

## Порядок работы по фазам (обязательно)

1. **Перед фазой — вопросы.** Без ограничения количества, группами по 4 через AskUserQuestion, с вариантами ответа; рекомендуемый вариант первым, с пометкой «(Recommended)». Если фаза затрагивает внешний вид, обязательно спрашивать про дизайн (цвета, композиция, анимации, тексты) и показывать варианты наглядно (ASCII-схема, 2–3 описанных варианта). **Не начинать, пока владелец не ответит.**
2. Выполнить фазу.
3. Запустить `npm run lint`, `npm run typecheck`, `npm run build`, `npm test` (+ `npm run test:e2e`, `npm run i18n:check`, `npm run db:test`, когда они есть) и исправить все ошибки.
4. Коммит `feat(phase-N): …` (для фазы 0 — `chore(phase-0): …`), пуш в `main`.
5. Отчёт владельцу на русском: что сделано, как проверить руками (URL, тестовые логины), какие решения принял сам, какие TODO ждут его данных. Для визуальных фаз — скриншоты Playwright на 360px и 1440px (светлая и тёмная тема).
6. Вопросы по результату и **стоп до подтверждения**.

Решения, которые дорого переделывать (схема БД, алгоритм корзины, источники цен, модель AI, оплата, URL-структура), — остановиться и спросить даже посреди фазы.

## Стек

- Next.js (App Router) + TypeScript `strict`, без `any`
- Tailwind CSS + shadcn/ui, Framer Motion (анимации только `transform`/`opacity`, уважать `prefers-reduced-motion`)
- next-intl: языки `lt` (эталон) и `ru`
- React Hook Form + Zod: одни схемы на клиенте и сервере
- Supabase: Postgres (+ `pg_trgm`), Auth, Storage. **RLS на всех таблицах.** Схема — SQL-миграции в `supabase/migrations/`, типы генерируются (`npm run db:types`), тесты RLS — pgTAP в `supabase/tests/`
- AI: Anthropic API, только с сервера, structured output по Zod. `AI_MODEL` (чат, по умолчанию `claude-sonnet-5-5`), `AI_RECIPE_MODEL` (генерация и перевод рецептов, `claude-opus-5-5`)
- Меню и корзина: собственные `lib/planner/` и `lib/basket/` (жадная сборка + локальный поиск), детерминированные, работают без AI
- Сбор цен: скрипты в `scripts/`, запуск GitHub Actions по понедельникам; CSV-импорт в админке
- Оплата: только Stripe (подписки, пробная неделя без карты, разовый платёж, Customer Portal; налоги — Stripe)
- Письма: Resend + react-email. Антиспам: Cloudflare Turnstile + rate limit
- Аналитика: своя анонимная (без cookies), дашборд в админке. Сторонние пиксели — только после согласия
- Деплой Vercel; тесты Vitest + Playwright

```
npm run ingredients:check     # CSV каталога + USDA: схема, дубли, калории ≈ БЖУ
npm run ingredients:import    # каталог → БД (идемпотентно; в CI после миграций)
npm run usda:extract          # пересобрать data/seed/usda_sr_legacy.json из USDA SR Legacy
npm run ingredients:verify    # both_stores / missing в БД + data/availability.json (после сбора цен)

npm run prices:scrape -- --store barbora|rimi [--limit N] [--dry-run]   # локально: NODE_USE_ENV_PROXY=1

```
(Команды появляются по мере фаз; если команды ещё нет — создать её в той фазе, где она нужна.)

## Код-стайл

- Компоненты ≤ ~200 строк; бизнес-логика — в `lib/`, не в компонентах.
- Никаких строк интерфейса в компонентах: только `messages/{lt,ru}.json`. Контент из БД — JSONB `{ "lt": "...", "ru": "..." }`, `lt` обязателен.
- Форматы: `58,49 €`, даты `2026-11-18`, метрическая система (через общие форматтеры в `lib/i18n/format.ts`).
- Server-only код (ключи, Stripe, AI, service role Supabase) — в файлах с `import 'server-only'`.
- Zod-схемы для всех входов API и ответов AI.
- Секреты только в переменных окружения; в коде, логах, чате и коммитах — никогда. Ключи у владельца запрашиваются через защищённую форму, сначала объяснить, что и зачем.
- Коммиты маленькие и понятные; в сообщениях коммитов не упоминать идентификаторы моделей.

## Магазины (решение владельца)

- На старте **только Barbora (Maxima e-parduotuvė) и Rimi**. Lidl, Iki и Maxima-магазин нигде не упоминаются (анкета, сравнение, тексты, подсказки AI). Таблица `stores` остаётся расширяемой.
- Рецепт может использовать только ингредиенты уровня `both_stores` (продаются и в Barbora, и в Rimi; есть подтверждённый матч, товар в наличии). CI падает, если рецепт ссылается на другой ингредиент.

## Цены: каждая цена — с источником и временем проверки

- У каждой цены в БД и в интерфейсе есть `source` (`scraper:barbora`, `scraper:rimi`, `csv:<файл>`) и `checked_at`.
- В корзину идёт только цена, проверенная не более **14 дней** назад. Старше — «nepatikrinta», в расчёт не входит.
- Никаких выдуманных, «примерных» или захардкоженных цен и сумм. Демо-цифры на главной считаются из реальных данных (пересчёт по понедельникам).
- Аномалии (изменение > 50 %, пропажа товара) → очередь проверки в админке; до подтверждения в корзину не идут.
- У каждой цены в интерфейсе — отметка источника и даты (tooltip «Barbora · patikrinta 2026-11-16»). Подпись: «Kainos atnaujinamos kas pirmadienį iš Barbora ir Rimi e. parduotuvių. Parduotuvėje kaina gali skirtis.»
- Сбор цен вежливый: публичные страницы, разрешённые robots.txt, 1 запрос в 2 с, User-Agent с контактом. Юридическая оценка — `TODO: проверить юристом` (`docs/legal-todo.md`).

## Безопасность питания (SPEC §9, обязательно)

- **Аллергены — жёсткое исключение в коде.** Ни AI, ни замена блюда, ни «Kita savaitė», ни демо не могут его обойти. Тесты на каждый путь; эти тесты обязаны проходить всегда.
- Аллергены рецепта = объединение аллергенов ингредиентов; для готовых товаров — по составу; **неизвестный состав → «нельзя»** для аллергика.
- Подпись: «Patikrinkite sudėtį ant pakuotės — gamintojai keičia receptūras.»
- Минимальная калорийность и максимальный темп похудения — в `lib/nutrition/safety.ts` (`TODO: проверить диетологом`); ниже порога меню не строится, мягкое объяснение.
- До 18 лет — без дефицита калорий; беременность, кормление, болезни → без дефицита и «aptarkite su gydytoju».
- Тон без «draudžiama», «palūžote», «blogas maistas»; никаких «до/после».
- «Tai nėra medicininė konsultacija» — в футере, анкете и ответах AI.
- **AI не придумывает цены, КБЖУ и аллергены.** AI только переводит текст в параметры по Zod-схеме; меню и корзину считает детерминированный алгоритм. Ни одно число КБЖУ или цена не берётся из ответа AI.
- В AI не передаются имя и e-mail. Данные о здоровье — отдельное явное согласие, минимум данных, экспорт и удаление.

## Честность

- Никаких выдуманных отзывов, числа пользователей, «рекомендуют диетологи». Все числа (рецептов, экономии) — из БД.
- Пустые реквизиты в `lib/config.ts` на сайте не показываются.

## Готовность фазы (SPEC §17)

lint, typecheck, build, тесты без ошибок · проверено на 360 / 768 / 1440 px, светлая и тёмная тема · `i18n:check` проходит · новые таблицы с RLS и тестами · тесты аллергенов зелёные · ни одной цены без `source` и свежего `checked_at` · с фазы 6 ни одного рецепта с ингредиентом не уровня `both_stores` · отчёт, скриншоты, вопросы.
